# 水表测试程序执行流程详解

## 程序架构总览

### 主循环结构
```c
int main(void) {
    test_Init();           // 系统初始化
    while(1) {
        Uart3_Rx_rec();    // 计量模块通信处理
        Uart4_Rx_rec();    // 红外模块通信处理
        Uart1_Rx_rec();    // 水表设备通信处理
        Uart0_Rx_rec();    // PC上位机通信处理
        LED_FLAG_LOOP();   // LED状态显示
        test_Loop_Func();  // 主测试状态机
        Test_loop_func();  // 辅助测试功能
        FL_IWDT_ReloadCounter(IWDT); // 看门狗喂狗
    }
}
```

## 程序启动和触发机制

### 1. 程序启动触发
**触发方式**: PC上位机发送启动指令
**协议格式**: `68 AA 长度 工位号 模块号[6] 表局类型 超声波参数[6] 机械表参数[6] 校验 16`

**触发位置**: `PC_xieyi_Ctrl.c` 中的 `PC_xieyijiexi()` 函数
```c
if(zufuchua[pHead]==0x68 && zufuchua[pHead+1]==0xAA) {
    // 解析启动参数
    memcpy(Test_jiejuo_jilu.mokuaihao, &zufuchua[pHead + 4], 6);
    Test_jiejuo_jilu.biaoju_leixing_famen = zufuchua[pHead + 10];
    memcpy(Test_jiejuo_jilu.chaoshengbo_canshu, &zufuchua[pHead + 11], 6);
    memcpy(Test_jiejuo_jilu.jixiebiao_canshu, &zufuchua[pHead + 17], 6);

    test_start();  // 启动测试流程
    PC_xieyifasong_1();  // 发送启动确认
}
```

### 2. 测试启动初始化
**函数**: `test_start()`
**初始化动作**:
- IO口复位: `test_start_Init()`
- 测试结果清零: `test_jieguo_qingling()`
- 设置测试状态: `Test_liucheng_L = w_start`
- 设置超时保护: `time_aroundtest_ms = 100000` (100秒总超时)

## 核心状态机流程

### 状态机变量
- **主状态**: `enum Test_liucheng Test_liucheng_L`
- **协议状态**: `enum test_xieyi_jilu test_xieyi_jilu_Rec`
- **时间控制**: `struct Test_quanju_canshu Test_quanju_canshu_L`

### 详细状态转换流程

#### 状态1: w_wait (等待状态)
```
动作: 无动作，等待PC指令启动
跳转条件: PC发送启动指令
下一状态: w_start
跳转位置: PC_xieyijiexi() → test_start() → Test_liucheng_L = w_start
```

#### 状态2: w_start (电源检测)
```
动作:
- 检测VCC电源电压
- 调用: get_zhukongban_gongdian_dianya()

跳转条件:
- 电压正常(3200-4000mV): 进入下一步
- 电压异常: 延时1秒重试

跳转逻辑:
if (zhidian_dianya_gongdian > 3200 && zhidian_dianya_gongdian < 4000) {
    Test_liucheng_L = w_qiehuan_kongshui;  // 电压正常
    danbu_chaoshishijian_ms = 20000;       // 设置20秒超时
} else {
    time_softdelay_ms = 1000;              // 延时1秒重试
}
```

#### 状态3: w_qiehuan_kongshui (切换空水状态)
```
动作:
- 发送计量模块空水指令: JILIAN_wushui_xieyi()
- 等待计量模块确认: w_get_kongshui

通信协议: 68 AA 07 00 00 校验 16
- 00: 空水状态码
- 00: 流量大小(空水为0)

跳转条件:
- 收到确认(test_xieyi_jilu_Rec == w_get_kongshui): 进入功耗检测
- 未收到确认: 每2秒重发一次

跳转逻辑:
if (test_xieyi_jilu_Rec == w_get_kongshui) {
    Test_liucheng_L = w_gonghao_CHK;       // 进入空管功耗检测
    time_softdelay_ms = 2000;              // 延时2秒
    danbu_chaoshishijian_ms = 20000;       // 20秒超时
}
```

#### 状态4: w_gonghao_CHK (空管功耗检测)
```
动作:
- 检测空管状态功耗: Current_CHK_Func(0)
- 功耗范围: 2-30 (单位可能是μA或mA)

跳转条件:
- 功耗正常(2-30): 进入满水状态切换
- 功耗异常: 延时1秒重试

跳转逻辑:
if (zhidian_jingtai_gonghao > 2 && zhidian_jingtai_gonghao < 30) {
    Test_liucheng_L = w_qiehuan_manshui;   // 进入满水状态
    danbu_chaoshishijian_ms = 10000;       // 10秒超时
}
```

#### 状态5: w_qiehuan_manshui (切换满水状态)
```
动作:
- 发送计量模块满水指令: JILIAN_manshui_xieyi()
- 等待计量模块确认: w_get_manshui

通信协议: 68 AA 07 01 00 校验 16
- 01: 满水状态码
- 00: 流量大小(满水静止为0)

跳转条件: 同空水状态切换
下一状态: w_gonghao_manshui_CHK
```

#### 状态6: w_gonghao_manshui_CHK (满水功耗检测)
```
动作: 检测满水状态功耗
跳转条件: 功耗正常(2-30)
下一状态: w_qiehuan_zoushui
```

#### 状态7: w_qiehuan_zoushui (切换走水状态)
```
动作:
- 发送计量模块走水指令: JILIAN_zoushui_xieyi()
- 等待计量模块确认: w_get_zoushui

通信协议: 68 AA 07 02 05 校验 16
- 02: 走水状态码
- 05: 水流大小等级

跳转条件: 同上述状态切换
下一状态: w_gonghao_zoushui_CHK
```

#### 状态8: w_gonghao_zoushui_CHK (走水功耗检测)
```
动作: 检测走水状态功耗
跳转条件: 功耗正常(2-30)
下一状态: w_diancitie_huanxing_irda
```

#### 状态9: w_diancitie_huanxing_irda (电磁铁换向)
```
动作: 无具体动作(可能是物理换向延时)
跳转条件: 直接跳转
下一状态: get_biaohao
超时设置: 10秒
```

#### 状态10: get_biaohao (获取表号)
```
动作:
- 发送读取表号协议: find_biaohao_xieyi()
- 协议: TONGXIN_xieyifasong(0x2031, 0x02, moren_biaohao, kongshujuyu, 0)

等待响应: test_xieyi_jilu_Rec == w_get_biaohao
重试间隔: 3秒
下一状态: get_banbenhao

跳转逻辑:
if (test_xieyi_jilu_Rec == w_get_biaohao) {
    Test_liucheng_L = get_banbenhao;
    shangg_chongfa = 0;  // 重发计数清零
}
```

#### 状态11: get_banbenhao (获取版本号)
```
动作:
- 发送读取版本号协议: find_banbenhao_xieyi()
- 协议: TONGXIN_xieyifasong(0x2011, 0x02, dangqian_biaohao, kongshujuyu, 0)

版本号解析: 解析类似"1.2.3"格式的版本字符串
存储: Test_jiejuo_jilu.banbenhao[2]
下一状态: w_zhudong_shangg
超时设置: 15秒
```

#### 状态12: w_zhudong_shangg (主动上报)
```
动作:
- 发送上报协议: send_shanggao_xieyi()
- 协议: TONGXIN_xieyifasong(0xF001, 0x02, dangqian_biaohao, kongshujuyu, 0)

重试机制: shangg_chongfa计数器，最多重试1次
等待响应: test_xieyi_jilu_Rec == w_get_shanggao
下一状态: w_shangg_jieguo_start

特殊处理: 如果重试超过1次或收到响应，设置红外检测标志
Test_jiejuo_jilu.hongwai_jiance = 1;
```

#### 状态13: w_shangg_jieguo_start (开始查询上报结果)
```
动作:
- 发送F003专用协议: Test_zhuanyong_xieyi()
- 协议: TONGXIN_xieyifasong(0xF003, 0x02, dangqian_biaohao, kongshujuyu, 0)

等待响应: test_xieyi_jilu_Rec == w_get_test_zhuanyong
延时设置: 10秒 (通信建立延时)
超时设置: 60秒 (长时间等待)
下一状态: w_shangg_jieguo
```

#### 状态14: w_shangg_jieguo (查询上报结果)
```
动作:
- 持续发送F003查询协议
- 解析返回的所有测试数据

数据处理 (解析F003协议返回的数据):
- CSQ信号强度
- Flash检测状态
- 主电、备电电压值
- 各种传感器状态
- IMEI、IMSI、ICCID信息
- GP30电压等

关键判断:
if (L_chaosheng_shunshiliuliang > 0) {
    Test_jiejuo_jilu.jiliang_jiance = 1;  // 计量检测通过
}

硬件动作:
- 开启到位信号: daowei_1_ON(), daowei_2_ON()

下一状态判断:
- 正常: w_famenceshi (阀门测试)
- 特殊情况: 如果阀门参数特定值为0x00，直接跳到 w_end
```

#### 状态15: w_famenceshi (阀门测试)
```
动作:
- 发送阀门开启协议: FM_Open_xieyi()
- 协议: TONGXIN_xieyifasong(0xC022, 0x04, dangqian_biaohao, {0x1D}, 1)

并行检测 (在Test_loop_func中):
- 检测阀门1电压: get_famen_1_dianya()
- 检测阀门2电压: get_famen_2_dianya()
- 电压判断: > 1800mV为高电平，否则为低电平

状态记录:
- FM1, FM2记录高低电平状态 (0x01=高, 0x02=低)
- 完整状态: 0x03 = 高低都检测到

跳转条件:
if (Test_jiejuo_jilu.FM1 == 0x03 && Test_jiejuo_jilu.FM2 == 0x03) {
    Test_jiejuo_jilu.FM = 1;              // 阀门测试通过
    test_xieyi_jilu_Rec = w_get_famen_dongzuo_L;  // 设置完成标志
}

下一状态: w_end
```

#### 状态16: w_end (测试结束)
```
动作:
- 硬件复位: 关闭所有控制信号
- 设置测试完成标志: test_over = 1
- 返回等待状态: Test_liucheng_L = w_wait

硬件操作:
- 主电源保持: zhudian_gongdian_On()
- 备电源关闭: beidian_gongdian_OFF()
- 霍尔传感器关闭: huuoer_1_OFF(), huuoer_2_OFF()
```

## 时间控制机制

### 软件延时系统
```c
struct Test_quanju_canshu {
    uint16_t time_softdelay_ms;        // 软件延时(状态间延时)
    uint32_t time_aroundtest_ms;       // 总测试超时(100秒)
    uint16_t danbu_chaoshishijian_ms;  // 单步超时时间
    uint8_t test_over;                 // 测试结束标志
};
```

### 超时保护机制
```c
void test_err_end_Func() {
    if ((time_aroundtest_ms == 0 || danbu_chaoshishijian_ms == 0) &&
        test_over == 0) {
        test_testend();  // 强制结束测试
    }
}
```

### 延时跳转逻辑
```c
if (Test_quanju_canshu_L.time_softdelay_ms > 0)
    return;  // 延时期间不执行状态机
```

## 通信协议交互

### PC上位机协议 (UART0)
| 协议类型 | 格式 | 功能 |
|----------|------|------|
| 启动测试 | 68 AA 长度 工位 模块号[6] 类型 参数... | 启动测试流程 |
| 查询结果 | 68 AC 长度 工位 16 | 查询测试结果 |

### 水表设备协议 (UART1)
| 协议ID | 功能 | 格式 |
|--------|------|------|
| 0x2031 | 读取表号 | 标准帧格式 |
| 0x2011 | 读取版本号 | 标准帧格式 |
| 0xF001 | 上报指令 | 标准帧格式 |
| 0xF003 | 专用查询 | 标准帧格式 |
| 0xC022 | 阀门控制 | 带数据域 |

### 计量模块协议 (UART3)
| 状态码 | 功能 | 格式 |
|--------|------|------|
| 0x00 | 空水状态 | 68 AA 07 00 00 校验 16 |
| 0x01 | 满水状态 | 68 AA 07 01 00 校验 16 |
| 0x02 | 走水状态 | 68 AA 07 02 05 校验 16 |

## 错误处理和重试机制

### 1. 通信重试
- **协议发送**: 每个协议都有重试机制，间隔1-3秒
- **超时保护**: 每个状态都有单步超时时间
- **全局超时**: 总测试时间100秒超时

### 2. 状态恢复
- **异常处理**: 超时或错误时强制跳转到w_end状态
- **硬件复位**: 测试结束时恢复所有IO状态

### 3. 数据验证
- **电压范围**: VCC电压必须在3200-4000mV
- **功耗范围**: 各状态功耗必须在2-30范围内
- **协议校验**: 所有通信协议都有CRC或和校验

## 测试数据流向

### 输入数据源
1. **PC上位机**: 测试参数、启动指令、结果查询
2. **水表设备**: 设备信息、状态数据、传感器数据
3. **计量模块**: 水状态确认、计量数据
4. **硬件检测**: 电压、功耗、阀门状态

### 输出数据
1. **实时调试**: 通过UART0发送调试信息
2. **测试结果**: 完整的测试数据结构
3. **状态指示**: LED显示当前测试状态
4. **控制信号**: 各种硬件控制输出

## 关键时序要求

| 阶段 | 延时时间 | 超时时间 | 重试间隔 |
|------|----------|----------|----------|
| 电源检测 | 0ms | 3s | 1s |
| 水状态切换 | 2s | 20s | 2s |
| 功耗检测 | 0ms | 10s | 1s |
| 通信协议 | 1-3s | 10-60s | 2-3s |
| 阀门测试 | 0ms | 16s | 8s |
